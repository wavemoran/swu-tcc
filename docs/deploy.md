# Deploying

Production is the Worker `swu-tcc` on the Cloudflare Workers Free plan,
served at https://swu-tcc.win (a Workers Custom Domain; `workers_dev` and
preview URLs are off in `apps/worker/wrangler.jsonc`).

## Workers Builds (normal path)

Cloudflare's own CI deploys every push to `main`. Cloudflare has no GitHub
OIDC, so this keeps Cloudflare credentials out of GitHub entirely: the
Cloudflare GitHub app has access to this one repository and Cloudflare
generates its own build token. Branch protection on `main` (PR plus passing
checks) is what makes "every push to `main`" safe.

Settings (Workers & Pages → `swu-tcc` → Settings → Build):

| Setting | Value |
|---|---|
| Git repository | `wavemoran/swu-tcc` |
| Production branch | `main` |
| Root directory | `/` (repo root; `.nvmrc` selects Node 26) |
| Build command | `npm run build -w @swu-tcc/web` (Workers Builds already runs `npm clean-install` first) |
| Deploy command | `npx wrangler deploy --config apps/worker/wrangler.jsonc` |
| Builds for non-production branches | off |
| API token | generated by Cloudflare |
| Build variables | none (Wrangler telemetry is off via `send_metrics: false` in `wrangler.jsonc`) |

`package.json` pins `packageManager: npm@11.x` because the build image
otherwise uses npm 10, which ignores the `allowScripts` install-script gate.
Bump it together with local npm (and only to a release at least 7 days old).

Free plan: 3,000 build minutes a month and one build at a time; a build takes
a couple of minutes.

## Manual deploy (fallback)

Needs the Cloudflare API token (Workers Scripts: Edit, this account only) kept
outside the repo. From the repo root:

```sh
npm ci && npm run build -w @swu-tcc/web
cd apps/worker
CLOUDFLARE_ACCOUNT_ID=… CLOUDFLARE_API_TOKEN=… npx wrangler deploy
```

Never print the token. After any deploy, `npx wrangler tail swu-tcc --format json`
shows live requests, CPU time and the structured `evt: api` log line.

## Emergency stop

Set `TCC_DISABLED` to `"1"` (every `/api` route answers 503 `disabled`) and
deploy, or roll back in the dashboard: Workers & Pages → `swu-tcc` →
Deployments → pick an earlier version → Deploy.
